## 1. HYPRLAND

### 1.1 Config language / hyprland.conf structure

URL (opened):
https://wiki.hypr.land/Hypr-Ecosystem/hyprlang/
- hyprlang is "a library that implements parsing for the hypr
  configuration language."
- Line style: `COMMAND = VALUE`. Command can be a variable or a
  special keyword. Variables are like "options" (specified once, later
  overwrites earlier); keywords are like "commands" (invoke behaviour
  every time they are defined).
- Categories: `category { variable = value }`. Special categories take
  a key, e.g. two `special { key = A ... }` / `special { key = B ... }`
  groups — "Hyprland for example uses those for per-device configs."
- Defining variables: `$VAR = myData`; use inline, e.g.
  `$SUFFIX = -san`, `$NAME = Jeremy`, `greeting = Hello, $NAME$SUFFIX.`
- Comments start with `#`; escape as `##` for a literal `#`.
- Inline option form: `category:variable = value` (used by
  `hyprctl keyword`); special category: `category[keyvalue]:variable = value`.
- Error suppression blocks: `# hyprlang noerror true` ... `# hyprlang noerror false`.
- Basic arithmetic in `{{ }}` (0.6.3+) and `# hyprlang if` conditionals
  (0.6.4+) also documented on this page.

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Configuring-Hyprland
- "The config is located in `~/.config/hypr/hyprland.conf`."
- Specific file via `--config` / `-c` argument.
- Hyprland auto-generates an example config if none exists; removing
  the line `autogenerated=1` removes the yellow warning.
- "The config is reloaded the moment you save it" or manually with
  `hyprctl reload`.
- "Start a section with `name {` and end in `}` in separate lines!"
- Every line is `COMMAND=VALUE` (spaces allowed: `COMMAND = VALUE`).
- Variables page covers toggleable/numerical options; Keywords page
  covers binds/curves/execs/monitors etc.

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Keywords
- Keywords are not variables, they are "commands".
- Comma rule: you cannot reduce the number of commas for an empty arg.
- Executing: `exec-once=command` executes only on launch;
  `exec=command` executes on each reload.
- Defining variables: `$VAR = value`, e.g. `$MyFavoriteGame = Among Us`;
  combine in place, e.g. `col.active_border=ff$MyRedValue1111`.
- Sourcing (multi-file): `source=~/.config/hypr/myColors.conf` —
  parsing is LINEAR (above lines, then sourced file, then below lines).
- Per-device: `device { name = ...  # options ... }`, name from
  `hyprctl devices`; only explicitly changed values overwrite `input`.
- Environment: `env = XCURSOR_SIZE,24`, `env = QT_QPA_PLATFORM,wayland`
  (no quotes around values); `envd = XCURSOR_SIZE,24` also exports to
  D-Bus (systemd only). `env` works like `exec-once` (fires once at launch).
- Layer blur example: `layerrule = blur,NAMESPACE` /
  `layerrule = unset,NAMESPACE`; namespaces from `hyprctl layers`.
- Wallpaper is NOT the default Hyprland background image; use a
  wallpaper utility such as hyprpaper or swaybg (named on this page).

Canonical default-config pattern (from example configs quoted in
search results for the wiki URLs above — treat as pattern, not a
fetched wiki page): 
  $mainMod = SUPER
  $terminal = kitty
  $fileManager = dolphin (variants: thunar / nemo / pcmanfm)
  $menu = wofi --show drun   (variants: `wofi -n`, `rofi -show drun`, fuzzel)
  exec-once = waybar
  exec-once = dunst
  monitor = ,preferred,auto,1   /   monitor=,highrr,auto,1

### 1.2 Variables — gaps / borders / rounding / opacity (REAL names)

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Variables/#variable-types
Variable types: int, bool (true/false, yes/no, on/off, 0/1), float,
color, vec2, MOD, str, gradient (`color color ... [angle]`, e.g.
`rgba(11ee11ff) rgba(1111eeff) 45deg`).
Colors: `rgba(b3ff1aee)`, `rgb(b3ff1a)`, legacy `0xeeb3ff1a` (ARGB).
Mod list: `SHIFT CAPS CTRL/CONTROL ALT MOD2 MOD3 SUPER/WIN/LOGO/MOD4 MOD5`.

### 1.3 Tiling layouts

URL (opened):
https://wiki.hypr.land/Configuring/Dwindle-Layout/
- "Dwindle is a BSPWM-like layout, where every window on a workspace
  is a member of a binary tree."
- "Dwindle splits are NOT PERMANENT. The split is determined
  dynamically with the W/H ratio of the parent node. If W > H, it's
  side-by-side. If H > W, it's top-and-bottom. You can make them
  permanent by enabling `preserve_split`."
- Category name: `dwindle`. Real variables (default):
  `pseudotile` false ("Pseudotiled windows retain their floating size
  when tiled"), `force_split` 0 (0=follows mouse, 1=always left/top,
  2=always right/bottom), `preserve_split` false, `smart_split` false,
  `smart_resizing` true, `permanent_direction_override` false,
  `special_scale_factor` 1, `split_width_multiplier` 1.0,
  `use_active_for_splits` true, `default_split_ratio` 1.0
  (1 = even 50/50, range 0.1–1.9), `split_bias` 0, `precise_mouse_move` false.
- Dispatcher: `pseudo` toggles a window's pseudo mode.
- Layout messages via `layoutmsg`: `splitratio`, `togglesplit`
  (requires preserve_split), `swapsplit`, `preselect` (one-time split
  direction override, e.g. `bind = SUPER, A, layoutmsg, preselect l`),
  `movetoroot`.

URL (opened):
https://wiki.hypr.land/Configuring/Layouts/Master-Layout/
- "The master layout makes one (or more) window(s) be the 'master',
  taking (by default) the left part of the screen, and tiles the rest
  on the right."
- Category name: `master`. Real variables (default):
  `mfact` 0.55 ("`mfact = 0.70` would mean 70% of the screen will be
  the master window, and 30% the slave", range 0.0–1.0),
  `new_status` "slave" ("master": new window becomes master; "slave":
  added to slave stack; "inherit": inherit from focused window),
  `new_on_top` false, `new_on_active` "none",
  `orientation` "left" (left/right/top/bottom/center),
  `allow_small_split` false, `special_scale_factor` 1,
  `slave_count_for_center_master` 2, `center_master_fallback` "left",
  `smart_resizing` true, `drop_at_cursor` true,
  `always_keep_position` false, `focus_master_on_close` false.
- Layout messages: `swapwithmaster`, `focusmaster`, `cyclenext`,
  `cycleprev`, `swapnext`, `swapprev`, `addmaster`, `removemaster`,
  `orientationleft/right/top/bottom/center/next/prev/cycle`,
  `mfact` (relative delta e.g. -0.2/+0.2 or `exact 0.5`),
  `rollnext`, `rollprev`.
- NOTE version drift: this current page frames messages as
  `hl.dsp.layout("cyclenext")` (Lua). The 0.41.0 equivalent surface is
  `bind = $mainMod, ..., layoutmsg, cyclenext` etc.

Selecting the layout: `general { layout = dwindle }` or `layout = master`
(Variables page, `general:layout`, default dwindle).


### 1.4 Keybinds — syntax, $mainMod, flags, dispatchers, workspaces

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Binds/
- Basic syntax, verbatim: `bind=MODS,key,dispatcher,params`
  Example: `bind=SUPER_SHIFT,Q,exec,firefox` binds SUPER+SHIFT+Q.
- No modkey: leave MODS empty — `bind=,Print,exec,grim`.
- Keycode binding: `bind=SUPER,code:28,exec,amongus` (28 = T).
  Keysym names are the segment after `XKB_KEY_` in xkbcommon-keysyms.h;
  find keys with `xev` / `wev`.
- Unbind: `unbind=SUPER,O`; dynamic: `hyprctl keyword unbind SUPER,O`.
- Mouse buttons: prefix `mouse:` — `bind=SUPER,mouse:272,exec,amongus`
  (272 = LMB, 273 = RMB). Mouse wheel: `mouse_down` / `mouse_up`
  (also `mouse_left`/`mouse_right`), e.g.
  `bind=SUPER,mouse_down,workspace,e-1`.
- Switches: `bindl=,switch:[switch name],exec,swaylock` (+ `switch:on:` /
  `switch:off:` variants); switches listed by `hyprctl devices`.
- Multiple binds to one key execute in order (top to bottom).
- Bind flags — format `bind[flags]=...`, e.g. `bindrl=MOD,KEY,exec,...`:
  l = locked (works under lockscreen/input inhibitor)
  r = release (trigger on release)
  e = repeat (repeat when held)
  n = non-consuming (also passes event to active window)
  m = mouse (see bindm)
  t = transparent (cannot be shadowed)
  i = ignore mods
  Examples on page: `binde=, XF86AudioRaiseVolume, exec, wpctl set-volume -l 1.5 @DEFAULT_AUDIO_SINK@ 5%+`,
  `bindl=, XF86AudioLowerVolume, exec, wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-`,
  `bindr=SUPER, SUPER_L, exec, pkill wofi || wofi` (toggle wofi),
  `bindel=, XF86AudioRaiseVolume/LowerVolume, ...`,
  `bindl=, XF86AudioMute, exec, wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle`.
- Mouse binds: `bindm=ALT,mouse:272,movewindow`; available:
  `movewindow`, `resizewindow` (param 1 = keep aspect, 2 = ignore
  keepaspectratio rule). Also usable with keyboard keys as the "click".
- Global binds: `bind = SUPER,F10,pass,^(com\.obsproject\.Studio)$`,
  `bind = SUPER,F10,sendshortcut,SUPER,F4,^(com\.obsproject\.Studio)$`,
  DBus portal: `bind = SUPERSHIFT, A, global, coolApp:myToggle`
  (requires XDPH; list via `hyprctl globalshortcuts`).
- Submaps (modes): `bind=ALT,R,submap,resize`, then `submap=resize`,
  `binde=,right,resizeactive,10 0` etc., `bind=,escape,submap,reset`,
  `submap=reset`. Catch-all: `bind=,catchall,submap,reset`.
  Recovery: `hyprctl dispatch submap reset`.

$mainMod pattern (verified in example configs quoted in search results
referencing the wiki Binds page — the wiki itself defines variables in
Keywords, §1.1 above):
  $mainMod = SUPER # Sets "Windows" key as main modifier
  bind = $mainMod, Q, killactive,
  bind = $mainMod, C, killactive,
  bind = $mainMod, E, exec, $fileManager
  bind = $mainMod, V, togglefloating,
  bind = $mainMod, R, exec, $menu
  bind = $mainMod, P, pseudo,        # dwindle
  bind = $mainMod, J, togglesplit,   # dwindle
  bind = $mainMod, left, movefocus, l   (also right/up/down = r/u/d)
  bind = $mainMod, 1, workspace, 1   ...  bind = $mainMod, 0, workspace, 10
  bind = $mainMod SHIFT, 1, movetoworkspace, 1  (etc. for 2..10)
  bindm = $mainMod, mouse:272, movewindow
  bindm = $mainMod, mouse:273, resizewindow
Spacing variant also seen: `bind = $mainMod, Q, killactive` (no trailing comma).

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Dispatchers/#list-of-dispatchers
Key dispatchers (name — params):
- `exec` command (supports rules), `execr` raw command, `pass` window,
  `sendshortcut` mod,key[,window], `killactive` none, `closewindow` window
- `workspace` workspace, `movetoworkspace`, `movetoworkspacesilent`
- `togglefloating` / `setfloating` / `settiled`
- `fullscreen` 0=fullscreen (entire screen), 1=maximize (keeps gaps and
  bar(s)), 2=fullscreen without altering internal state; `fakefullscreen`
- `pin`, `movefocus` direction, `movewindow`, `swapwindow`,
  `centerwindow`, `resizeactive`, `moveactive`, `cyclenext`,
  `focuswindow`, `focusmonitor`, `splitratio` floatvalue
- `renameworkspace` `id name` e.g. `2 work`, `exit`,
  `movecurrentworkspacetomonitor`, `focusworkspaceoncurrentmonitor`,
  `moveworkspacetomonitor`, `swapactiveworkspaces`
- `togglespecialworkspace` [name], `focusurgentorlast`, `togglegroup`,
  `changegroupactive`, `submap` reset-or-name, `global` name,
  `tagwindow`, `alterzorder`

Workspace parameter grammar (same page, "Workspaces" section) —
eight choices:
  ID e.g. `1`; Relative `+1`/`-3`; on-monitor relative/absolute
  `m+1`/`m~3`; on-monitor incl. empty `r+1`/`r~3`; open-workspace
  `e+1`/`e~2`; Name `name:Web`; `previous`; first empty `empty`
  (suffixes m/n, e.g. `emptynm`); Special `special` / `special:name`.
  Numeric IDs allowed ONLY 1..2147483647 (no 0, no negatives).
Special workspace = "scratchpad": toggleable on any monitor, multiple
named specials limited to 97 at a time. `special` is supported ONLY on
`movetoworkspace` and `movetoworkspacesilent` as a target in the note
on that page. Example: `bind = SUPER, C, movetoworkspace, special`.
Exec-with-rules: `bind = mod, key, exec, [rules...] command`, e.g.
`bind = SUPER, E, exec, [workspace 2 silent;float;noanim] kitty`.

Workspace RULES keyword (pattern from configs/search snippets; the
authoritative selector props below are from the hyprland-wiki
Workspace-Rules content summarised in search results):
  workspace = 1, monitor:eDP-1
  workspace = 2, monitor:DP-1, default:true
  workspace = 1, defaultName:$ws1, persistent:true, id:1
  workspace = name:dev, ...   workspace = special, ...
Workspace selectors for rules: `w[tX]` tiled count, `w[vX]` visible
count, `w[gX]` groups, `f[N]` fullscreen state (-1 none, 0 fullscreen,
1 maximized, 2 fake fullscreen), `s[bool]` special, `m[monitor]`.
This enables "smart gaps": e.g. window/workspace rules removing
borders/rounding/gaps on `onworkspace:w[t1]`, `w[tg1]`, `f[1]`.

### 1.5 Window rules

URL (opened):
https://wiki.hypr.land/0.41.0/Configuring/Window-Rules/
- Rules are CASE SENSITIVE (`firefox` != `Firefox`).
- V1 syntax: `windowrule=RULE,WINDOW` where WINDOW is a RegEx for
  class, or `title:` + regex. Examples:
  `windowrule=float,^(kitty)$`
  `windowrule=move 0 0,title:^(Firefox)(.*)$`
- V2 syntax: `windowrulev2 = float,class:(kitty),title:(kitty)` —
  match multiple fields. Supported V2 fields: `class`, `title`,
  `initialclass`, `initialTitle`, `tag`, `xwayland` 0/1, `floating` 0/1,
  `fullscreen` 0/1, `pinned` 0/1, `focus` 0/1, `workspace`,
  `onworkspace`. At least one field required. Inspect windows with
  `hyprctl clients` (it prints `initialClass`, config uses `initialclass`).
- Static rules (evaluated once at open): `float`, `tile`, `fullscreen`,
  `fakefullscreen`, `maximize`, `move [x] [y]`, `size [x] [y]`,
  `center ([opt])`, `pseudo`, `monitor [id]`, `workspace [w]`
  (add `silent` to open silently, `unset` to clear), `nofocus`,
  `noinitialfocus`, `pin` (floating only), `stayfocused`,
  `suppressevent [fullscreen|maximize|activate|activatefocus]`,
  `group [...]`, `unset`, `nomaxsize`.
- Dynamic rules (re-evaluated on property change): `opacity [a]`
  (1, 2 or 3 floats = overall / active+inactive / +fullscreen;
  `override` makes it exact instead of a multiplier — opacity is a
  PRODUCT by default), `rounding [x]`, `bordersize [size]`,
  `bordercolor [c]`, `noblur`, `noborder`, `noshadow`, `noanim`,
  `nodim`, `minsize`, `maxsize`, `dimaround`, `idleinhibit
  [none|always|focus|fullscreen]`, `keepaspectratio`, `xray`, `tag`.
- Canonical example: `windowrulev2 = suppressevent maximize, class:.*`
  `windowrulev2 = bordercolor rgb(FF0000) rgb(880808),fullscreen:1`
  `windowrule = rounding 10,^(kitty)$`
  `windowrulev2 = stayfocused, class:^(pinentry-)`
- Rules are processed top-to-bottom; LAST match takes precedence.
- Layer rules (bars, launchers, wallpapers, notifications are layers,
  not windows): `layerrule = rule, namespace` or `layerrule = rule,
  address:0x[hex]`; rules include `blur`, `noanim`, `unset`;
  namespaces from `hyprctl layers`.

### 1.6 Ecosystem — Waybar / Wofi / Dunst (autostarted via exec-once)

Typical autostart block (pattern verified across configs in search
results + Keywords exec-once semantics):
  exec-once = waybar
  exec-once = dunst
  (also commonly: hyprpaper/swww-daemon, hypridle, nm-applet,
   blueman-applet, wl-paste --watch cliphist store, swaync as a
   Dunst alternative)

URL (opened):
https://manpages.ubuntu.com/manpages/noble/man5/waybar.5.html
- Waybar config is JSON, named `config`. Valid locations:
  `$XDG_CONFIG_HOME/waybar/config`, `~/.config/waybar/config`,
  `~/waybar/config`, `/etc/xdg/waybar/config`. Styling is a separate
  CSS stylesheet (waybar-styles(5) in other manpages).
- Bar options (real names): `layer` (default bottom; top = in front),
  `output` (string|array, `!` excludes, `*` wildcard), `position`
  (default top; top/bottom/left/right), `height`, `width`,
  `modules-left`, `modules-center`, `modules-right` (arrays),
  `margin`, `margin-<top|left|bottom|right>`, `spacing`, `name`
  (CSS class), `mode` (dock/hide/invisible/overlay), `start_hidden`,
  `exclusive` (default true — requests exclusive zone so windows do
  not draw under the bar), `fixed-center` (default true),
  `passthrough`, `gtk-layer-shell`, `ipc`, `id`, `include`.
- Minimal example from the manpage:
  { "layer": "top",
    "modules-left": ["sway/workspaces", "sway/mode"],
    "modules-center": ["sway/window"],
    "modules-right": ["battery", "clock"],
    "battery": { "format": "{capacity}% {icon}" },
    "clock": { "format-alt": "{:%a, %d. %b  %H:%M}" } }
  (In Hyprland setups the `sway/*` modules are replaced by
  `hyprland/workspaces`, `hyprland/window`, etc. — module-name swap is
  a simulator design decision, the JSON structure above is verified.)
- Multiple bars: top-level JSON array of bar objects, one per output.
- Duplicate a module with a `#name` suffix, e.g. `"battery#bat2"`.

URLs (opened):
https://manpages.ubuntu.com/manpages/noble/man5/wofi.5.html
https://manpages.ubuntu.com/manpages/noble/en/man7/wofi.7.html
- Wofi is "a rofi inspired launcher for wlroots compositors";
  `$menu = wofi --show drun` is the standard Hyprland binding target.
- Built-in modes (wofi(7), exactly 3): `run` (searches $PATH for
  executables), `drun` (searches $XDG_DATA_HOME/applications and
  $XDG_DATA_DIRS/applications for .desktop files), `dmenu` (reads
  stdin, prints selection to stdout). Combi: `--show mode1,mode2,...`.
- XDG defaults stated on wofi(7): if $XDG_DATA_HOME is not specified
  it defaults to ~/.local/share; if $XDG_DATA_DIRS is not specified
  it defaults to /usr/local/share:/usr/share.
- Config (wofi(5)): simple key=value pairs in snake_case, `#` comments;
  most options mirror CLI flags (`--show` = `show=`/`mode=`).
  Real options: `width` default 50%, `height` default 40%,
  `prompt`, `xoffset`/`x`, `yoffset`/`y`, `normal_window` false
  (true = normal window instead of wlr-layer-shell), `allow_images`,
  `allow_markup`, `cache_file` default $XDG_CACHE_HOME/wofi-<mode>
  (or ~/.cache), `term` (terminal run order: kitty, alacritty,
  wezterm, foot, termite, gnome-terminal, weston-terminal),
  `matching` contains/multi-contains/fuzzy (default contains),

Full FHS directory table (from the FHS summary in search results —
Wikipedia's FHS article, URL returned by search:
https://en.wikipedia.org/wiki/Filesystem_Hierarchy_Standard ,
plus the FHS text snippets above). Use these exact purposes in the
simulator's VFS:
- `/` — root, primary hierarchy, container of the entire hierarchy
- `/bin` — essential command binaries for all users (cat, ls, cp, rm…)
- `/boot` — boot loader files (kernel, initrd)
- `/dev` — device files (incl. /dev/null, /dev/urandom in snippets)
- `/etc` — host-specific system configuration files (static only,
  no binaries); /etc/opt for /opt packages, /etc/X11 for X11
- `/home` — user home directories, one subdir per user (root excluded)
- `/lib` — essential shared libraries for /bin and /sbin + kernel modules
- `/media` — mount point for removable media
- `/mnt` — mount point for temporarily mounted filesystems
- `/opt` — add-on application software packages (self-contained subdirs)
- `/proc` — virtual fs: process and kernel information as files
- `/root` — home directory for the root user (NOT the same as `/`)
- `/run` — run-time variable data since last boot (FHS 3.0, 2015);
  cleared/truncated at boot, often tmpfs
- `/sbin` — essential system binaries (fsck, init, route)
- `/srv` — site-specific data served by the system (web/FTP/VCS)
- `/sys` — devices, drivers, kernel features (sysfs)
- `/tmp` — temporary files, often not preserved across reboots
- `/usr` — secondary hierarchy, shareable read-only user data:
  /usr/bin non-essential binaries for all users, /usr/sbin,
  /usr/lib, /usr/include, /usr/share (incl. /usr/share/man),
  /usr/libexec
- `/usr/local` — tertiary hierarchy, local data specific to this host
  (own bin/lib/share); where admin-compiled software goes, NOT the
  package manager
- `/var` — variable data: /var/log, /var/lib, /var/cache, /var/spool,
  /var/run (legacy), /var/tmp, /var/mail, /var/opt
Ubuntu/Debian note (from search snippets): modern Ubuntu merges
/bin, /sbin, /lib into /usr (the "usr merge"); the old paths remain
as symlinks, so /bin/bash and /usr/bin/bash are the same file.

Permissions model (for the simulator's VFS; standard Ubuntu, snippet-
corroborated in §2.1/§2.2 sources): owner/group/other x read/write/
execute; `chmod` changes mode (644 = regular file default,
755 = directory/executable default, umask 022), `chown` changes
owner, `ls -l` displays them; executing/traversing a directory needs
its `x` bit. Sensitive example: /etc/shadow is 600 root:root.
[Mark in final docs: the numeric-mode examples are from secondary
search snippets, not from an opened Ubuntu page — re-verify in
`man chmod` / Ubuntu Server docs before treating as cited.]
